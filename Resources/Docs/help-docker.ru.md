# Docker

Запуск инстанса не локальным бинарником, а внутри Docker-контейнера. Полезно, когда нужный бэкенд (CUDA, ROCm, SYCL) проще получить готовым образом, чем собирать на хосте.

Вкладка появляется, только если в системе найден Docker CLI. Если её нет — установите Docker и перезапустите приложение.

## Параметры

- **Запускать в Docker** — главный переключатель. Пока он выключен, остальные поля не действуют, и сервер стартует обычным способом.
- **Образ** — имя образа, например `ghcr.io/ggml-org/llama.cpp:server-cuda`. Образ должен уже быть скачан либо доступен для `docker pull`.
- **Использовать все GPU** — передаёт контейнеру `--gpus all`. Требует настроенного NVIDIA Container Toolkit на хосте.
- **Удалять контейнер при остановке** — `--rm`, не оставлять остановленные контейнеры.
- **Имя контейнера** — фиксированное имя вместо случайного. Удобно для `docker logs`, но при одновременном запуске нескольких инстансов имена должны различаться.

## Что учитывать

- **Пути монтируются из хоста**: путь к модели должен быть виден внутри контейнера. Проще всего держать модели в одном каталоге и указывать его в **Папке моделей**.
- **Порт** с вкладки **Основное** пробрасывается наружу — обращайтесь к серверу по адресу хоста, как обычно.
- Определение возможностей (`llama-server --help`) выполняется для того бинарника, который указан на вкладке **Основное**. Если у образа набор флагов отличается, пометки поддержки в интерфейсе могут не совпадать с реальностью.
- Полная команда, включая `docker run`, видна в предпросмотре внизу окна.

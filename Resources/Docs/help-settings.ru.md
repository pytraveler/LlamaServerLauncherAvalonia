# Настройки приложения

Настройки самого лаунчера. Они общие для всех профилей и в профили не сохраняются.

## Оформление

Тема (тёмная / светлая), цветовая схема, размер и семейство шрифта интерфейса. Ниже — блок произвольных цветов: можно переопределить фон окна, панелей, акцент, разделители, цвет блоков команд, три положения переключателей и цвет полосы загрузки, а кнопкой сброса вернуть значения схемы.

Цвет полос загрузки и обновления задаётся темой приложения и не зависит от системного акцента, поэтому не может оказаться неразличимо серым. Индикаторы нагрузки оборудования (CPU, RAM, GPU, VRAM, температура) сохраняют собственные цвета.

## Обновления

Периодичность автоматических проверок новых релизов — отдельно для приложения и для llama.cpp. Слишком частые проверки упираются в лимиты GitHub API, о чём предупреждает подсказка под полями. Найденное обновление показывается кнопкой в шапке главного окна.

## Хранение данных

Где лежат профили, настройки, логи, бенчмарки и скачанные сборки llama.cpp. По умолчанию — системная папка данных пользователя; можно указать свою (например, на другом диске). При смене каталога предлагается перенести туда уже накопленные данные.

## Стриминг логов

Встроенный сервер логов, чтобы смотреть их с другого устройства.

- Включение и **порт**; опциональный **токен** для доступа.
- `http://localhost:<порт>/` — встроенная веб-страница просмотра с автоскроллом и переподключением.
- `ws://localhost:<порт>/ws?token=<токен>` — поток логов по WebSocket.
- `/api/logs/history` и `/api/status` — история и состояние в JSON.

Изменение порта или токена требует перезапуска сервера логов — для этого есть кнопка рядом.

## Прокси по запросу

OpenAI-совместимый обратный прокси: клиент сам «просит» нужную модель, а лаунчер поднимает соответствующий профиль.

1. Включите прокси, задайте порт и, при необходимости, API-ключ.
2. Направьте клиент (например Cherry Studio) на `http://<хост>:<порт>/v1`.
3. В поле `model` запроса укажите **имя профиля**.

Прокси запустит этот профиль, дождётся готовности и проксирует ответ, в том числе потоковый. Запуск профиля останавливает любой другой работающий — в VRAM всегда одна модель. По истечении **таймаута простоя** сервер останавливается сам (`0` отключает авто-выгрузку). Профили в режиме роутинга (`--models-dir`) в списке моделей не отдаются.

## Поведение

- **Автозапуск с системой** — регистрация приложения в автозагрузке ОС.
- **Подтверждать остановку сервера** — спрашивать перед остановкой работающего инстанса.
- **Монитор оборудования** — показ CPU / RAM / GPU / VRAM / температуры над списком инстансов. На время загрузки модели опрос приостанавливается, чтобы не мешать инициализации CUDA/HIP.
- **Авторазмер высоты окна** — подгонять высоту под содержимое.
- **Браузер** — каким браузером открывать WebUI: из списка найденных или по указанному пути.
- **ComfyUI** — перед загрузкой любого профиля дёрнуть эндпойнт ComfyUI `/free`, чтобы тот освободил VRAM. Позволяет передавать видеопамять между ComfyUI и llama.cpp без ручных действий.
- **Завершать запущенные сервером процессы вместе с ним** — сервер и всё его потомство помещаются в job-объект Windows, поэтому при остановке сервера, выходе из лаунчера и даже при его аварийном завершении не остаётся висящих процессов. Актуально для MCP-серверов: они сами запускают приложения (тот же ComfyUI), а обход дерева процессов до них не всегда доходит. Выключайте, если такое приложение должно продолжать работать после остановки сервера. Только Windows.
- **Сворачивать в трей** — кнопка сворачивания прячет окно в трей, где меню значка держит запущенные инстансы под рукой. Выключите — и свёрнутое окно останется на панели задач, как любое другое; значок в трее остаётся в любом случае.

## Экспериментальные репо

Свои GitHub-источники сборок llama.cpp помимо официального. Добавьте репозиторий, при желании — фильтр по тегу, и его релизы появятся в диалоге загрузки наравне с официальными. Периодичность проверки задаётся тут же.

# Спекулятивное декодирование

Приём ускорения генерации: маленькая «черновая» (draft) модель быстро предлагает несколько токенов вперёд, а основная модель проверяет их одним проходом. Совпавшие токены принимаются пачкой — выходит быстрее, чем генерировать их по одному. Качество ответа не меняется: всё, что не подтвердила основная модель, отбрасывается.

Раздел целиком опционален. Если ничего здесь не заполнять, сервер работает обычным образом.

## Когда это даёт выигрыш

- Основная модель большая и упирается в память, а draft-модель — маленькая и той же архитектуры/токенизатора.
- Текст предсказуемый (код, структурированные ответы) — там угадывание срабатывает чаще.

Если draft-модель промахивается слишком часто, скорость наоборот падает: проверка стоит времени. Имеет смысл замерить оба варианта — см. **Бенчмарки**.

## Общие параметры

- **Тип спекулятивного декодирования** (`--spec-type`) — режим работы; допустимые значения берутся из справки вашего бинарника.
- **Draft N-Max / N-Min** (`--spec-draft-n-max`, `--spec-draft-n-min`) — сколько токенов черновая модель предлагает за раз.
- **Draft P-Split / P-Min** (`--spec-draft-p-split`, `--spec-draft-p-min`) — пороги вероятности, при которых предположение принимается или отбрасывается.

## Draft-модель

- **Draft-модель** (`-md`) — путь к `.gguf` черновой модели, либо
- **HF-репозиторий draft** (`--hf-repo-draft`) — скачать её с HuggingFace.
- **GPU-слои draft** (`-ngld`) — сколько слоёв черновой модели выгрузить на видеокарту.

> Draft-модель занимает свою долю VRAM. Если её загрузка вынуждает уменьшить `-ngl` основной модели, выигрыш может быть съеден — проверяйте суммарный расход памяти.

# Основное — пути, модель, сеть

Здесь задаётся минимум, необходимый для запуска: чем запускать, что запускать и на каком адресе.

## Быстрый старт

1. **Исполняемый файл** — укажите свой `llama-server`, либо нажмите кнопку загрузки llama.cpp в шапке окна: приложение скачает официальный релиз с GitHub и само определит подходящую сборку под вашу видеокарту (CUDA / Vulkan / HIP / SYCL / CPU).
2. **Модель (-m)** — выберите файл `.gguf` кнопкой **Обзор…**, либо **Выбрать…** для списка с метаданными.
3. Нажмите **Запустить сервер** внизу окна и следите за логом.
4. Когда появится статус готовности — откройте WebUI кнопкой **Открыть в браузере**.

## Пути

- **llama-server** — бинарник сервера. Какая версия llama.cpp стоит сейчас, показывает подсказка кнопки **Сменить версию llama** в шапке окна (если версия скачана этим приложением и потому известна).
- **Модель** — конкретный файл `.gguf`. Под блоком путей выводится бейдж с данными из GGUF: квантизация, число параметров, слоёв и экспертов, наличие chat-шаблона и vision-проектора. Оттуда же берётся максимальная длина контекста, которой ограничивается поле **Размер контекста**.
- **Папка моделей** — режим роутинга (`--models-dir`): сервер сам выбирает модель по имени в запросе. Заполняйте либо **Модель**, либо **Папку моделей** — строка состояния под полями показывает, какой режим сейчас активен.
- **Выбрать…** — сканирует папку (при желании рекурсивно) и показывает фильтруемый список `.gguf` с размером, метаданными и меткой `mmproj`. Последняя папка запоминается.

> Если выбрать файл проектора `mmproj-*.gguf` в качестве основной модели, появится предупреждение — такой файл задаётся отдельным полем **MMProj** на вкладке **Параметры**.

Поля путей помнят историю: кнопка **∨** справа от поля показывает ранее введённые значения, соседняя кнопка с корзиной очищает поле.

## HuggingFace

Альтернатива локальному файлу — скачивание моделью самим llama.cpp:

- **Репозиторий** (`--hf-repo`) — например `user/model-GGUF`.
- **Файл** (`--hf-file`) — конкретный файл внутри репозитория.
- **Офлайн** (`--offline`) — работать только из кэша, без обращений к сети.

## Сетевые настройки

- **Хост** — по умолчанию `127.0.0.1` (доступ только с этого компьютера). Укажите `0.0.0.0`, чтобы открыть доступ по локальной сети.
- **Порт** — по умолчанию `8080`. Для каждого одновременно работающего инстанса нужен свой порт.

Некорректные значения подсвечиваются сообщением прямо под полями.

## Профили

Верхняя строка окна — это профили: полный набор настроек под именем. Введите имя, нажмите **Сохранить**; переключение в выпадающем списке загружает профиль. В меню кнопки **Сохранить** — переименование, клонирование, удаление, экспорт в JSON / `.bat` / `.sh` / `.command` и импорт.

Файлы `.json`, `.bat`, `.cmd`, `.sh`, `.command`, `.exe` и `.gguf` можно просто перетащить на окно.

Импорт - брошенный файл или пункт **Импорт** в меню - открывает поверх окна панель со списком того, что файл изменит: поле, текущее значение на форме, значение из файла и галочка. Показаны только отличия, поэтому файл, совпадающий с формой, так и говорит, а не открывает пустую панель. У профиля отмечено всё: `.json` хранит полный набор значений. `.bat` и `.sh` говорят только о тех флагах, которые в них есть, поэтому неупомянутые поля показаны без галочки и сохраняют то, что на форме, - поставьте галочку, если поле всё-таки надо очистить. Enter применяет отмеченное, Escape оставляет форму нетронутой. Панель отключается на вкладке **Поведение**, и тогда импорт перезаписывает всю форму, как раньше.

Звёздочка рядом с выпадающим списком добавляет выбранный профиль в избранное. Избранные профили держатся в начале списка, над разделительной чертой, и помечены звёздочкой рядом с именем, так что рабочие профили предлагаются первыми, а не ищутся прокруткой. Повторное нажатие звёздочки убирает профиль из избранного, а сам выбор запоминается между запусками.

Имя профиля, подсвеченное в списке предупреждающим цветом, ссылается на файлы, которых на диске больше нет — чаще всего это модели, перенесённые на другой диск. Наведите на него курсор, чтобы увидеть, какие именно пути пропали. Та же проверка выполняется при каждом запуске, каким бы способом он ни был начат, и называет пропавший путь в логе.

# MCP

Подключение внешних MCP-инструментов к запускаемому серверу. Список серверов хранится в профиле, а перед стартом лаунчер собирает из него файл `mcp.json` и передаёт его в llama-server через `--mcp-servers-config`.

Поддерживается только транспорт stdio: llama-server сам запускает указанную команду дочерним процессом и общается с ней по JSON-RPC через стандартный ввод-вывод. Ничего запускать заранее не нужно.

Флаг появился в llama.cpp не сразу. Если выбранная сборка его не знает, вкладка это покажет, а сам флаг в команду не попадёт.

## Как это работает

1. При старте llama-server поднимает каждый сервер один раз, спрашивает список инструментов и гасит его.
2. Инструменты публикуются под именем `имя_инструмент` (имя сервера из первого поля плюс имя инструмента) и видны в `GET /tools`, в веб-интерфейсе и модели.
3. При первом вызове инструмента сервер запускается заново и живёт до конца работы llama-server.

Имя, совпадающее с уже зарегистрированным инструментом, пропускается.

## Список на вкладке

Каждый сервер занимает одну строку: переключатель "Выкл / Вкл", имя и команда. Клик по строке открывает отдельное окно редактирования, так что вкладка остаётся короткой независимо от числа серверов, а длинный список прокручивается внутри своей рамки.

## Параметры сервера

Задаются в окне редактирования (клик по строке или "Добавить сервер"). Правки применяются по кнопке "Сохранить", "Отмена" оставляет профиль нетронутым.

- **Имя** — ключ в `mcp.json` и префикс имён инструментов.
- **Команда** — исполняемый файл. Запись без команды llama-server пропускает. Команда ищется по PATH так же, как это делает llama-server: сначала точное имя, затем расширения из PATHEXT. На Windows это важно: рядом с `npx.cmd` в каталоге Node лежит файл `npx` без расширения (скрипт для POSIX), точное имя выигрывает, и запуск падает с "not a valid application". В таком случае пишите `npx.cmd` явно.
- **Аргументы** — одной строкой, кавычки учитываются; в файл попадают массивом.
- **Рабочий каталог** — необязателен, каталог дочернего процесса.
- **Таймаут** — ограничение одного вызова инструмента, по умолчанию 30000 мс.
- **Переменные среды** — по одной паре `KEY=VALUE` в строке; добавляются к среде лаунчера.

Кнопка **Проверить** в окне редактирования запускает команду так же, как это сделает llama-server, выполняет рукопожатие MCP и показывает список инструментов прямо там. Это дешёвый способ найти ошибку заранее: неверный конфиг не даёт llama-server стартовать вообще.

Кнопка **Запросить** на вкладке читает `GET /tools` у уже запущенного сервера этого профиля. Результат приходит всплывающим сообщением с числом инструментов, а по клику открывается окно со списком: раздел MCP - инструменты от MCP-серверов, раздел встроенных - собственные инструменты llama-server.

## Что учитывать

- Дочерние процессы работают с правами лаунчера. Добавляйте только те команды, которым доверяете.
- MCP-сервер может запускать собственные приложения, и они переживают сессию, если сам сервер их не гасит. Чтобы после остановки llama-server не оставалось висящих процессов, на вкладке **Настройки -> Поведение** есть галочка "Завершать запущенные сервером процессы вместе с ним" (включена по умолчанию, Windows): сервер со всем потомством держится в job-объекте и гибнет целиком.
- При включённом MCP llama-server ограничивает CORS до localhost, если `--cors-origins` не задан явно. Для доступа с другой машины задайте этот аргумент на вкладке **Свои аргументы**.
- Вызовы инструментов требуют jinja-шаблонов. Для сервера они включены по умолчанию, но `--no-jinja` в своих аргументах их выключит.
- Прогрев занимает до 10 секунд на сервер, это добавляется ко времени старта.
- В режиме Docker файл монтируется в каталог `/mcp` внутри контейнера, но сами команды должны существовать в образе.
- Импорт понимает формат Cursor и Claude Desktop: объект `mcpServers` с командами, аргументами и переменными среды. В выпадающем меню рядом с кнопкой перечислены профили, у которых уже есть MCP-серверы, с числом серверов в скобках - выбор такого профиля копирует его серверы в текущий, не трогая исходный.
- Если тот же флаг задан вручную на вкладке **Свои аргументы**, приоритет у него, а сгенерированный файл не подставляется.
